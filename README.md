# 신입사원 온보딩 자동화 시스템 

대한민국 기업의 신입사원 입사 준비 업무를 기준으로 만든 로컬 웹 프로그램입니다.
관리자가 코드를 수정하지 않고 프로그램 제목, 메뉴/툴 이름, 표시 여부, 순서, 기능명, 권한, 담당자 규칙, 온보딩 템플릿, 필수/권장 업무와 문서 양식을 관리할 수 있습니다.

## Windows 실행
1. Python 3.11 이상 설치
2. ZIP 압축을 새 폴더에 해제
3. `run.bat` 실행
4. 브라우저에서 `http://127.0.0.1:8000` 접속

기존 v1.1 데이터를 이어서 쓰려면 기존 폴더의 `onboarding.db` 파일과 `uploads` 폴더를 v1.2 폴더로 복사한 뒤 실행하세요. v1.2가 필요한 DB 항목을 자동 확장합니다.

## v1.2 주요 개선사항
### 오류/운영 안정성
- 입사취소된 업무가 지연/알림에 다시 잡히던 문제 수정
- 취소 업무를 전체 진행률 계산에서 제외
- 입사일 도래 시 `입사예정 → 재직` 자동 전환
- 입사일을 미래로 변경하면 상태를 다시 `입사예정`으로 보정
- Excel/수기 등록 시 중복 입사자 방지
- 알림 확인/업무 완료/취소 시 오래된 알림 정리
- 최신 FastAPI/Starlette `TemplateResponse` 방식 유지

### 실제 운영 기능
- 개별 입사자에게 템플릿 외 업무 직접 추가
- 개별 업무의 업무명/담당부서/담당자/완료기한/필수·권장/메모 수정
- 개별 업무 취소 및 재활성화(삭제 대신 이력 보존)
- 입사자 기본 인사정보 수정
- 소속부서·직위/직책·고용형태 변경 시 조건에 맞는 템플릿 재선택 가능
- `현재 템플릿 다시 반영`: 완료/취소 업무는 보존하고 신규·미완료 업무만 최신화
- 담당자 규칙이 바뀐 경우 템플릿 재반영으로 미완료 업무 담당자 갱신

### 입사서류 제출·확인
- 관리자 `문서·양식 관리`의 활성 양식을 입사자별 목록에 자동 연결
- 신입사원/인사담당자 문서 제출 및 재제출
- 인사담당자 `미제출 / 제출 / 확인완료 / 보완요청` 처리
- 확인 메모와 변경 이력 저장
- 양식 다운로드 및 제출파일 다운로드
- 업로드 허용 형식 제한(PDF/Office/이미지) 및 10MB 크기 제한

### 권한/개인정보 접근 개선
- 신입사원 역할은 전체 입사자 목록에 접근하지 못함
- 인사담당자가 특정 입사자의 `신입사원 화면 미리보기`를 선택하면 해당 입사자 데이터만 표시
- 실제 사내 로그인/SSO 연결 전 권한 테스트용 구조임을 화면에 명확히 표시

### 데이터 관리
- Excel 일괄등록 결과에 `등록 / 중복 제외 / 오류` 건수 표시
- Excel 내보내기에 `입사서류` 시트 추가
- 기존 관리자 설정 JSON 백업/복원 유지
- `전체 데이터베이스 백업` 추가: 입사자·업무·서류상태·설정 전체 포함
- 관리자 설정 복원 시 문서/양식 메타데이터까지 복원

### 화면/설정
- 메뉴/툴 이름 변경 지점을 `메뉴·툴 구성 관리`로 통합
- 주요 메뉴명을 변경하면 왼쪽 메뉴와 화면 제목이 함께 변경
- 대시보드에 `담당자 확인 필요` 건수 추가
- 입사취소자/취소업무 표시 개선

## 핵심 사용 흐름
1. `관리자 설정`에서 프로그램명, 메뉴, 권한, 담당자 규칙 설정
2. `온보딩 템플릿`에서 직무/부서/고용형태 조건과 필수·권장 업무 설정
3. `문서·양식 관리`에서 근로계약/보안/개인정보 등의 양식 등록
4. `입사자 관리`에서 입사자 등록
5. 조건에 맞는 템플릿 → 담당자 → 완료기한이 자동 생성
6. 담당자가 업무 완료 처리
7. 신입사원/인사담당자가 입사서류 제출, 인사담당자가 확인
8. 임박/지연/에스컬레이션 업무를 `알림 및 지연업무`에서 확인
9. 필요 시 개별 업무 추가/수정, 입사일 변경, 템플릿 재반영
10. Excel 또는 DB 백업으로 데이터 보관

## 현재 의도적으로 남긴 제한
- 실제 사내 로그인/SSO 계정 인증은 아직 연결하지 않았습니다. 현재 역할 전환은 개발/권한 확인용입니다.
- 이메일/Teams/Slack 외부 알림 전송은 아직 연결하지 않았습니다. 현재는 프로그램 내부 알림함 방식입니다.
- 외부 전자서명(DocuSign 등), AD/메일 계정 자동 생성, 사내 결재 시스템 자동 승인/반려는 회사별 API/보안정책이 필요하므로 실제 연동 단계에서 구현해야 합니다.
- `전체 DB 백업`은 다운로드 기능입니다. 전체 DB 복원은 실행 중 DB 교체 위험이 있어 버튼으로 자동화하지 않았습니다. 관리자 설정은 JSON으로 복원할 수 있습니다.

## GitHub 포트폴리오 관점
이 저장소는 특정 회사의 실제 인사정보를 포함하지 않습니다. `onboarding.db`와 `uploads/`의 실제 운영자료는 `.gitignore`로 제외합니다.

프로젝트의 설계 의도와 시연 포인트는 [`PORTFOLIO_GUIDE.md`](PORTFOLIO_GUIDE.md)에 정리했습니다.

## 기술 구성
- Backend: FastAPI
- UI: Jinja2 + CSS
- Database: SQLite
- Excel import/export: openpyxl

## 데이터 보호
실제 입사자 정보, 제출서류, SQLite DB는 GitHub에 커밋하지 않는 것을 전제로 합니다. 공개 저장소에서 시연할 경우 반드시 가상 데이터만 사용하세요.
