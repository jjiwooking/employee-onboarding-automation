# 신입사원 온보딩 자동화 시스템
### Employee Onboarding Automation System

> 신입사원이 입사하기 전부터 입사 후까지 필요한 업무를  
> **누가, 무엇을, 언제까지 해야 하는지 한 화면에서 관리하는 온보딩 업무관리 시스템**입니다.

---

## 🚀 바로 보기

- **GitHub 저장소:** https://github.com/jjiwooking/employee-onboarding-automation
- **Streamlit Demo:** https://employee-app-automation-6myex6plqjwpjnz8jarjsp.streamlit.app

> 공개 Streamlit 버전은 포트폴리오용 데모입니다.  
> 입력한 데이터는 영구 보존되지 않을 수 있으며 실제 개인정보를 입력하지 않는 것을 권장합니다.

---

# 1. 왜 만들었나요?

신입사원 한 명이 입사할 때 생각보다 많은 부서가 움직입니다.

예를 들어:

```text
근로계약서 작성
인사정보 등록
사원증 신청
회사 계정 생성
PC 및 업무장비 준비
교육 일정 등록
부서 업무 안내
보안서약 확인
필수서류 제출
```

이 업무들은 인사팀 혼자 처리하지 않습니다.

```text
인사팀
IT 담당자
부서장
교육 담당자
보안 담당자
신입사원
```

등 여러 담당자가 동시에 움직여야 합니다.

그래서 실제 업무에서는 이런 문제가 생길 수 있습니다.

```text
누가 담당자인지 모름
업무가 누락됨
기한을 넘김
담당자가 바뀌었는데 반영되지 않음
입사 일정이 변경됨
서류가 제출됐는지 다시 확인해야 함
신입사원마다 진행상태를 따로 확인해야 함
```

이 프로그램은 이런 반복적인 온보딩 업무를 한 곳에서 관리하기 위해 만들었습니다.

---

# 2. 한 문장으로 설명하면

> **신입사원을 등록하면 부서·직무에 맞는 온보딩 업무를 자동으로 생성하고,  
> 담당자·기한·서류·진행상태·지연업무까지 한 번에 관리하는 프로그램입니다.**

---

# 3. 전체 업무 흐름

```text
신입사원 등록
      ↓
부서 / 직무 확인
      ↓
온보딩 템플릿 자동 적용
      ↓
업무 자동 생성
      ↓
담당부서 / 담당자 지정
      ↓
기한 관리
      ↓
미완료 / 지연 업무 추적
      ↓
서류 제출 및 확인
      ↓
예외 처리
      ↓
완료 이력 및 진행상태 확인
```

단순한 체크리스트가 아니라

> **“입사자 등록 → 업무 생성 → 담당 → 기한 → 처리 → 기록”**

까지 이어지는 업무 흐름을 목표로 설계했습니다.

---

# 4. 대시보드

첫 화면에서는 현재 온보딩 상황을 빠르게 확인할 수 있습니다.

예:

```text
등록 입사자    3명
입사 예정      2명
전체 업무     21건
지연 업무      9건
전체 진행률   0%
```

그리고 신입사원별 진행상태와 지금 확인해야 할 업무를 바로 볼 수 있습니다.

예:

```text
김하늘 / 개발팀 / 백엔드 개발 / 입사예정
이도윤 / 영업팀 / 해외영업 / 입사예정
박서연 / 인사 / 인사운영 / 재직
```

대시보드의 목적은 단순한 통계가 아니라:

> **“지금 어떤 입사자와 업무를 먼저 확인해야 하는가?”**

를 빠르게 확인하는 것입니다.

---

# 5. 신입사원 등록

신규 입사자의 기본 정보를 등록합니다.

예:

```text
이름
소속부서
직무
입사일
고용형태
근무지
상태
```

입사자를 등록하면 프로그램은 해당 부서와 직무에 맞는 온보딩 템플릿을 적용할 수 있습니다.

---

# 6. 중복 등록 방지

동일한 입사자가 실수로 여러 번 등록되지 않도록 중복 여부를 확인합니다.

수동 등록뿐만 아니라 Excel을 이용한 일괄 등록에서도 중복을 확인하도록 설계했습니다.

---

# 7. 입사자 정보 수정

입사자의 정보가 변경되면 기존 데이터를 삭제하고 다시 등록할 필요가 없습니다.

예:

```text
소속부서 변경
직무 변경
입사일 변경
고용형태 변경
상태 변경
```

등의 기본정보를 수정할 수 있습니다.

---

# 8. 온보딩 템플릿

신입사원마다 매번 같은 업무를 하나씩 만들면 시간이 많이 걸립니다.

그래서 자주 사용하는 업무 묶음을 **온보딩 템플릿**으로 관리합니다.

예:

## 개발팀 템플릿

```text
근로계약서 작성
인사정보 등록
사원증 신청
사내 계정 생성
PC 및 업무장비 준비
개발환경 계정 생성
부서 업무 안내
필수교육 등록
```

## 영업팀 템플릿

```text
근로계약서 작성
인사정보 등록
사원증 신청
메일 계정 생성
노트북 준비
CRM 계정 신청
영업자료 안내
필수교육 등록
```

입사자를 생성할 때 직무와 부서에 맞는 템플릿을 자동으로 연결할 수 있습니다.

---

# 9. 템플릿 변경 후 기존 입사자 반영

회사 정책이나 온보딩 절차는 바뀔 수 있습니다.

예:

```text
기존
PC 준비
계정 생성

변경
PC 준비
계정 생성
보안교육 추가
```

템플릿을 변경한 후 기존 입사자에게도 새 업무를 반영할 수 있습니다.

이때 이미:

```text
완료된 업무
취소된 업무
```

는 최대한 유지하면서 새로운 업무를 추가하도록 설계했습니다.

---

# 10. 담당자 자동 배정

업무별 담당부서를 미리 지정할 수 있습니다.

예:

| 업무 | 담당부서 |
|---|---|
| 근로계약서 | 인사 |
| 인사정보 등록 | 인사 |
| 사원증 신청 | 총무 |
| 회사 계정 생성 | IT |
| PC 준비 | IT |
| 부서 업무 안내 | 소속부서 |
| 교육 일정 | 교육담당 |

이를 통해 신규 입사자가 등록될 때 어떤 부서가 어떤 업무를 처리해야 하는지 명확하게 구분합니다.

---

# 11. 담당자와 기한 관리

각 업무에는 다음 정보를 관리할 수 있습니다.

```text
업무명
담당부서
담당자
기한
상태
필수 / 권장
메모
```

예:

```text
업무명 : PC 및 업무장비 준비
담당부서 : IT
담당자 : 박IT
기한 : 2026-08-24
상태 : 진행중
```

---

# 12. 지연 업무 자동 확인

업무가 완료되지 않았는데 기한이 지나면 지연 업무로 표시합니다.

예:

```text
입사자 : 김하늘
업무 : PC 및 업무장비 준비
담당 : IT
기한 : 2026-08-24

→ 지연
```

대시보드에서는 이러한 업무를 따로 모아서 확인할 수 있습니다.

---

# 13. 입사자별 진행률

각 입사자별로 전체 온보딩 진행상태를 확인할 수 있습니다.

예:

```text
전체 업무 : 10건
완료 : 7건
진행중 : 2건
지연 : 1건

진행률 : 70%
```

담당자는 여러 입사자의 진행상태를 한 명씩 찾아보지 않고 한 화면에서 확인할 수 있습니다.

---

# 14. 입사일 기준 상태 관리

입사 전에는:

```text
입사예정
```

상태로 관리할 수 있습니다.

입사일이 되면 프로그램에서 재직 상태로 전환할 수 있도록 설계했습니다.

예:

```text
2026-08-24
입사예정

2026-08-25
재직
```

---

# 15. 개별 업무 추가

모든 온보딩 업무가 템플릿으로 해결되는 것은 아닙니다.

특정 입사자에게만 필요한 업무가 있을 수 있습니다.

예:

```text
해외출장 계정 신청
특수장비 교육
고객사 출입증 신청
보안등급 추가 승인
```

이런 업무는 해당 입사자에게 개별적으로 추가할 수 있습니다.

---

# 16. 업무 수정

이미 생성된 업무도 수정할 수 있습니다.

예:

```text
담당자 변경
담당부서 변경
기한 변경
필수 ↔ 권장 변경
메모 수정
```

실제 회사에서는 일정과 담당자가 자주 바뀌기 때문에 이를 예외가 아니라 일반적인 업무 흐름으로 고려했습니다.

---

# 17. 업무 취소 및 재활성화

입사 일정 변경이나 회사 사정으로 필요하지 않게 된 업무는 삭제하지 않고 **취소 상태**로 관리할 수 있습니다.

필요하면 다시 활성화할 수 있습니다.

이렇게 하면 업무가 왜 사라졌는지 추적할 수 있습니다.

---

# 18. 입사 취소 처리

입사가 취소된 경우 해당 입사자와 관련 업무가 일반적인 미완료 업무나 지연 업무에 포함되지 않도록 처리할 수 있습니다.

이를 통해 실제 진행해야 하는 업무와 취소된 케이스를 구분할 수 있습니다.

---

# 19. 문서 제출 관리

온보딩에서는 업무뿐 아니라 서류 관리도 중요합니다.

예:

```text
근로계약서
보안서약서
개인정보 동의서
통장사본
증명사진
기타 제출서류
```

입사자별로 문서 상태를 관리할 수 있습니다.

```text
미제출
제출
확인완료
보완요청
```

---

# 20. 문서 검토

입사자가 파일을 제출하면 인사담당자가 상태와 검토 메모를 남길 수 있습니다.

예:

```text
문서 : 통장사본
상태 : 보완요청

검토 메모 :
계좌번호가 일부 가려져 있어 재제출 요청
```

---

# 21. 파일 업로드 기본 보안

데모 버전에서는 업로드 가능한 파일 종류와 크기를 제한합니다.

예:

```text
PDF
Office 문서
이미지
```

파일 크기도 일정 범위 내에서 제한하도록 설계했습니다.

> 실제 기업 환경에서는 추가로 바이러스 검사, 접근권한, 암호화 저장 등이 필요합니다.

---

# 22. 신입사원용 화면

관리자 화면과 신입사원 화면에서 보여줘야 하는 정보는 다릅니다.

신입사원에게는 필요한 정보만 제한적으로 보여주는 구조를 고려했습니다.

예:

```text
내가 제출해야 할 문서
내가 확인해야 할 업무
진행상태
안내사항
```

관리자용 내부 정보는 불필요하게 노출하지 않는 것을 목표로 합니다.

---

# 23. 코드 없이 프로그램 수정

회사마다 사용하는 표현이 다릅니다.

예:

```text
신입사원
신규입사자
입사예정자
```

또는:

```text
온보딩 현황
입사 준비 현황
신규입사 진행현황
```

처럼 회사별로 용어가 다를 수 있습니다.

그래서 프로그램의 주요 요소를 코드에 고정하지 않고 관리자 화면에서 변경할 수 있도록 설계했습니다.

예:

```text
프로그램 제목
메뉴 이름
메뉴 순서
툴 / 기능 이름
안내문구
항목명
필수 / 권장
담당부서
```

즉:

> **운영자가 간단한 화면 변경을 위해 개발자에게 매번 코드를 요청하지 않는 것**

을 목표로 했습니다.

---

# 24. 필수 / 권장 업무 관리

모든 온보딩 업무의 중요도가 같은 것은 아닙니다.

예:

## 필수

```text
근로계약서
회사 계정
보안서약
필수교육
PC 준비
```

## 권장

```text
부서 소개자료
멘토 미팅
조직문화 안내
FAQ 안내
```

관리자가 직접 필수 / 권장을 지정해 관리할 수 있습니다.

---

# 25. 변경 이력

실제 업무에서는 누가 무엇을 변경했는지 확인할 필요가 있습니다.

예:

```text
담당자 변경
기한 변경
상태 변경
업무 취소
업무 재활성화
```

등의 변경 내용을 추적할 수 있도록 설계했습니다.

---

# 26. Excel 내보내기

온보딩 현황을 Excel 형태로 내보낼 수 있습니다.

예:

```text
입사자 현황
업무 현황
문서 제출 현황
완료 / 지연 현황
```

자료를 별도로 다시 정리하지 않고 보고나 공유에 활용할 수 있도록 했습니다.

---

# 27. 전체 데이터 백업

운영 데이터를 백업할 수 있도록 전체 DB 백업 기능을 포함했습니다.

> 공개 Streamlit 데모에서는 로컬 저장이 영구적이지 않을 수 있으므로 실제 회사 데이터 저장 용도로 사용하면 안 됩니다.

---

# 28. 가장 쉽게 테스트하는 방법

## STEP 1. 데모 초기화

Streamlit 앱 왼쪽 메뉴에서:

```text
데모 데이터 초기화
```

를 실행합니다.

샘플 입사자와 업무가 생성됩니다.

---

## STEP 2. 대시보드 확인

`온보딩 현황`에서:

```text
등록 입사자
입사 예정
전체 업무
지연 업무
전체 진행률
```

을 확인합니다.

서류 보완

완료 여부만 확인하는 것이 아니라 지연, 취소, 보완 등 실제 상태를 구분합니다.

# 38. 마무리

신입사원 온보딩에서 중요한 것은 업무가 많다는 사실이 아닙니다.

```text
무엇을 해야 하는가?
↓
누가 해야 하는가?
↓
언제까지 해야 하는가?
↓
완료됐는가?
↓
문제가 생기면 어떻게 처리했는가?
```

가 연결되어 있어야 합니다.

이 프로그램은 온보딩 업무를 단순 체크리스트에서 끝내지 않고:

> **등록 → 자동배정 → 기한관리 → 지연추적 → 문서관리 → 예외처리 → 완료기록**

까지 하나의 업무 흐름으로 관리하는 것을 목표로 제작했습니다.
